> 文档版本：1.0  
> 适用版本：V2（Heartbeat 和执行反馈）  
> 前提：已通过 `pnpm tauri dev` 启动应用，数据库已完成 migration v1~v4

---

## 使用说明

- 每个用例包含：**前置条件** → **操作步骤** → **预期结果**。
- 在每个用例末尾标注 `[ ] 通过` / `[ ] 失败`，方便逐项打勾。
- 章节顺序从基础到高级，建议按序执行。
- 标记 `⚠️` 的步骤是容易出错的风险点，请格外注意观察。

## 附录：快速搭建测试场景的技巧

### 快速触发 Heartbeat 事件

由于真实等待时间较长，可通过以下方式加速测试：

1. **缩短检查间隔**：在设置页将「检查间隔」设为 10 秒，关闭 Heartbeat 后重新开启
2. **构造已过期时间块**：手动输入 `start_time` 和 `end_time` 为过去的时间（例如 `2026-05-17 09:00` 到 `2026-05-17 09:30`），这样打开应用时 `getPendingFeedback` 会立即匹配到该块
3. **构造即将开始的时间块**：将 `start_time` 设为当前时间 + 1 分钟，可在约 1 分钟后触发提醒

### 数据库快速查看（可选）

使用 [DB Browser for SQLite](https://sqlitebrowser.org/) 打开 `time_manager.db` 文件（位于 `%APPDATA%\com.time-manager\` 或 Tauri 配置的数据目录），查看：

- `time_blocks` 表：确认 `reminder_sent_at`、`start_prompt_sent_at`、`end_prompt_sent_at`、`started_at`、`completed_at`、`skipped_at`、`delayed_at`、`feedback_note` 等 V2 新增字段
- `schema_version` 表：确认 version 1、2、3、4 均已插入
- `tasks` 表：验证 Task 状态联动结果
