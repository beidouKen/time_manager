# V3.6.2 Agent V2 Freeze Audit Plan

**日期**：2026-05-29  
**审查对象**：Agent V2 封板审查  
**项目版本映射**：Agent V2 对应整体项目 V3.6 / V3.6.2  
**结论规则**：9 个封板项全部通过，才允许进入 V2 封板。

---

## 一、审查目标

本轮审查不是功能扩展，而是确认 Agent V2 的边界已经收紧：

1. 用户输入先被 domain router 分发，而不是全部落入时间管理 parser。
2. 时间管理写操作只在明确、可执行、必要时经过确认后发生。
3. 非时间管理 handler 坚持只读，不触发工具、不写库、不返回刷新提示。
4. 所有用户可见文本都经过 ResponseBoundary，避免泄漏 intent / action / toolName / domain 等内部词。
5. Gold Test 和 build pipeline 能稳定证明以上行为。

---

## 二、审查流程

### 1. 静态边界审查

逐文件确认以下边界：

| 模块 | 审查点 | 通过标准 |
|---|---|---|
| `AgentDomainRouter` | 8 个 domain 的匹配顺序、关键词覆盖、低信号输入 | 时间管理请求进入 `time_management`；非时间管理请求进入对应 handler |
| `TimeManagementAgent` | exact / fuzzy / delete / reminder / future time 分支 | 写操作通过 ToolRouter 或确认流；推荐不直接写库 |
| `LLMDirectHandler` | 构造依赖与返回结构 | 不注入 ToolRouter / Service；不返回 `refreshHints` |
| `ExternalInfoHandler` | 实时信息响应 | 明确提示当前无法联网查询；不伪造天气/新闻/汇率/股价 |
| `ResponseBoundary` / `ResponseComposer` | 所有出口和 sanitize 规则 | confirmation、fallback、error、tool result 都走 boundary |
| `SemanticFrameParser` | 只做 time-management 内部语义 | 无 greeting / identity 分支；不承担全局 domain 分类 |
| `RecommendationPlanner` | timezone 与写库边界 | 候选按用户 timezone 计算；用户确认后才执行写入 |

### 2. Gold Test 审查

Gold Test 必须至少覆盖：

| 分类 | 最低要求 |
|---|---|
| 8 domain | `time_management`、`general_chat`、`knowledge_qa`、`writing_assistant`、`external_info`、`assistant_meta`、`feedback_or_complaint`、`low_signal` |
| fallback / low signal | 标点、空意图或低信息输入返回引导，不写库 |
| general_chat | 问候和普通闲聊不写库 |
| P0 时间管理 | 当前时间、明确创建 Task + TimeBlock、模糊推荐、推荐确认后写入、提醒、删除确认、未来时间、查询刚创建任务 |
| P0 边界 | 用户可见消息不包含内部名；非时间 handler 不写 Task / TimeBlock |

### 3. 手工抽查输入

封板前至少手工过一遍这些输入：

| 输入 | 预期 |
|---|---|
| `现在几点啊` | 进入 `time_management`，返回自然时间 |
| `我现在有一个写文档任务，10分钟，从现在开始` | 创建 Task + TimeBlock，返回 `refreshHints` |
| `帮我安排一个写文档任务，30分钟` | 生成候选和 `confirmationId`，不写库 |
| 点击确认推荐 | 创建 Task + TimeBlock，返回刷新提示 |
| `创建项目复盘任务，明天下午三点，30分钟` | 按未来时间创建 Task + TimeBlock |
| `明天下午三点提醒我开会` | 创建 `event` 类型 TimeBlock |
| `删除写文档任务` | 返回确认，不立即删除 |
| 点击确认删除 | 软删除任务，并刷新 task / timeline |
| `今天上海天气怎么样` | 提示未接入实时联网工具，不伪造数据 |
| `帮我写一首诗` | 只读回复，不写库 |
| `什么是番茄工作法` | 只读回复，不写库 |
| `?` | 返回低信号引导，不写库 |

### 4. 构建验证

封板前必须执行：

```powershell
pnpm.cmd exec tsc --noEmit
pnpm.cmd test
pnpm.cmd build
```

通过标准：

- `tsc --noEmit` 无错误。
- `pnpm test` 全部通过。
- `pnpm build` 成功；Vite chunk size warning 不阻塞封板，但需记录。

## 三、封板判定表

| # | 封板项 | 状态口径 |
|---|---|---|
| 1 | `AgentDomainRouter` 8 domain 正确路由 | Gold Test + 静态规则审查均通过 |
| 2 | `TimeManagementAgent` 主链路闭环 | exact / fuzzy / delete / reminder / future / refreshHints 均通过 |
| 3 | `LLMDirectHandler` 只读 | 无写库、无 ToolRouter、无 refreshHints |
| 4 | `ExternalInfoHandler` 诚实无工具提示 | 不造数据、不 fallback |
| 5 | `ResponseBoundary` / `ResponseComposer` 统一出口 | 所有可见消息走 boundary，内部名不外泄 |
| 6 | `SemanticFrameParser` 聚焦时间管理语义 | 无 greeting / identity；无“临时写作任务”特判；不直接决定写库 |
| 7 | `RecommendationPlanner` 候选与确认 | 使用 timezone；候选不写库；确认后才写入 |
| 8 | Gold Test | ≥16 cases，覆盖 8 domain + fallback + general_chat + P0 |
| 9 | Build | tsc / test / build 全绿 |

任一项失败，V2 不封板，失败项进入 V3.6.2 blocker 修复清单。
