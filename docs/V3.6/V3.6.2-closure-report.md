## 三、本轮关键收敛

### 3.1 推荐排程变为确认后写入

模糊时间输入，例如：

```txt
帮我安排一个写文档任务，30分钟
```

现在行为为：

1. `ActionPlanner` 输出 `request_recommendation`。
2. `RecommendationPlanner` 按用户 timezone 生成候选。
3. `TimeManagementAgent` 创建 pending confirmation，返回 `confirmationId` 和候选文案。
4. 用户确认后，`AgentService.confirmAction()` 执行 `schedule_task`。
5. 确认成功返回 `{ tasks: true, timeline: true, timelineDate }` 刷新提示。

这保证候选生成阶段不直接写库。

### 3.2 未来明确时间直接闭环

明确未来时间输入，例如：

```txt
创建项目复盘任务，明天下午三点，30分钟
```

现在会被解析为 absolute time anchor，并直接通过 `schedule_task` 创建 Task + TimeBlock。回复使用用户可见时间表达，不再误写成“现在开始”。

### 3.3 删除任务仍走强确认

删除输入先创建 `PendingConfirmation`，不立即执行 `delete_task`。确认后才软删除任务，并通过 `confirmAction` 返回刷新提示，保证 UI 能刷新 task / timeline。

### 3.4 ResponseBoundary 出口统一

`processInput()`、time-management handler、router handler、`confirmAction()`、`rejectAction()`、store catch fallback 均通过 boundary 或 boundary composer 生成用户可见消息。测试覆盖内部名清理，避免泄漏：

- `userGoal`
- `toolName`
- `ActionPlanner`
- `ToolRouter`
- `SemanticFrameParser`
- `delete_task`
- `create_reminder`
- `confirmation_required`
