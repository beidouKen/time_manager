# V3.8.3 Minimal Local Vector RAG

> 文档版本：1.0  
> 状态：已落地  
> 定位：在 V3.8.2 Demo Library 之上增加**最小但真实**的向量管线（chunk/query embedding → cosine → topK），Chat 主路径 **hybrid**（vector 优先，keyword fallback）。  
> **不是** GraphRAG / Agentic / Reranker / Coze API / sqlite-vec / pgvector。  
> **V3.9** 仍留给真向量库、多模型、Reranker 等完整闭环封板。

---

## 1. 本阶段是什么

| 能力 | 说明 |
|---|---|
| `rag_embeddings` (migration v8) | `vector_json` TEXT 存 `number[]`；`(chunk_id, model, version)` 唯一 |
| `EmbeddingProvider` | 接口 + `DeterministicEmbeddingProvider`（FNV-1a 桶 + L2，dim=64） |
| `VectorRagService` | embed / retrieveVector / retrieveHybrid |
| Chat 主路径 | `SqliteRagAdapter` 注入 `vectorService`，优先 hybrid |
| App 启动 | seed 后 `embedMissingChunks()` 幂等补向量 |
| 管理 UI | **仅文案**：检索预览仍 keyword；说明 Chat 已 vector/hybrid |

## 2. 本阶段不是什么

- GraphRAG / Agentic / Multi-Agent / HyDE / CRAG / Self-RAG / Reranker  
- Coze API / Dataset 同步  
- sqlite-vec / pgvector / 大型向量库  
- RAG 触发 ToolRouter / 写 tasks / time_blocks  
- `memory_summary` / `system_guidance` 进入普通 Chat 检索  
- 命名 **V3.9**

## 3. 数据模型（migration v8）

```sql
CREATE TABLE rag_embeddings (
  id                TEXT PRIMARY KEY,
  chunk_id          TEXT NOT NULL REFERENCES rag_chunks(id) ON DELETE CASCADE,
  document_id       TEXT NOT NULL,
  embedding_model   TEXT NOT NULL,
  embedding_version TEXT NOT NULL,
  vector_json       TEXT NOT NULL,
  dimensions        INTEGER NOT NULL,
  created_at        TEXT NOT NULL,
  updated_at        TEXT NOT NULL
);
CREATE UNIQUE INDEX uniq_rag_embeddings_chunk_model
  ON rag_embeddings(chunk_id, embedding_model, embedding_version);
```

## 4. EmbeddingProvider

- **`DeterministicEmbeddingProvider`**：`model=deterministic-local`, `version=v1`, `dimensions=64`；复用 `ragRanking.tokenize`；不调外部 API。  
- **`OpenAICompatibleEmbeddingProvider`**：草案类；缺 `apiKey` 即抛错；**默认不在 App / chatStore 启用**。  
- **`createDefaultEmbeddingProvider()`**：`VITE_RAG_EMBEDDING_PROVIDER=openai` 且 key 存在才切 OpenAI，否则 deterministic。

## 5. VectorRagService

| 方法 | 行为 |
|---|---|
| `embedMissingChunks` | 仅 active 文档；缺 embedding 的 chunk 批量 embed + INSERT（事务） |
| `retrieveVector` | query embed → JOIN active chunks + embeddings → 内存 cosine → topK |
| `retrieveHybrid` | vector ≥1 命中则返回；否则 `RagService.retrieve` 转 `retrieveMode='keyword'` |
| `refreshEmbeddingForDocument` | DELETE 旧 embeddings → 重 embed |

过滤与 keyword 一致：`status='active'`、`deleted_at IS NULL`、`sourceTypes` 硬过滤。

## 6. 接入点

- **`App.tsx`**：`runMigrations` → `seedRagKnowledge` → `new VectorRagService().embedMissingChunks()`；失败 `console.warn`。  
- **`chatStore.ts`**：`SqliteRagAdapter({ vectorService: new VectorRagService() })`。  
- **`RagRetrievePreviewPanel`**：仍走 `RagDemoLibraryService.previewRetrieve`（keyword）；副标题说明 Chat 主路径已 hybrid。

## 7. 安全边界（复述）

- RAG 只读；不写业务表；不调用 ToolRouter。  
- `user_material`：Settings toggle + 文档 active 双门控。  
- vector / keyword 共用相同 sourceType / status 过滤。  
- Adapter：vector 抛错 → 降级 keyword，不阻塞主响应。

## 8. 未来替换路径

抽象 `VectorStore`（sqlite-vec / pgvector / 远端）时：

1. 保留 `EmbeddingProvider` + `VectorRagService` 对外签名。  
2. 将 `retrieveVector` 的内存 cosine 换为 store 查询。  
3. `rag_embeddings.vector_json` 可迁移或双写。

完整闭环（多模型、真向量库、Reranker、生产级 hybrid 融合）稳定后再封板 **V3.9**；本轮仅 **V3.8.3**。
