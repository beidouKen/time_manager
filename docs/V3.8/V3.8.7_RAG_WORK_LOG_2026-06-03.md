### 2.2 RAG 已经接入 Agent 用户交互链路

当前 Chat 主路径中，`chatStore` 会创建 `SqliteRagAdapter` 并注入 `AgentService`。

交互路径为：

```text
User Input
  -> chatStore.sendMessage
  -> AgentService.processInput
  -> time_management domain
  -> RecommendationHandler
  -> SqliteRagAdapter
  -> RagEngine / HybridRetriever / VectorRagService / RagService fallback
  -> RAG snippet
  -> sanitizeRecommendation
  -> assistant message
```

也就是说，RAG 现在不只是数据库接口，而是可以参与用户可见回复。

但也需要准确说明：

当前还没有完全做到“RAG snippet 被注入 LLM prompt，并由 LLM 根据 RAG 规则亲自推理生成方案”。

目前更准确的状态是：

```text
RAG -> RecommendationHandler -> Agent response
```

而不是完整的：

```text
RAG -> LLM prompt/context -> LLM plan -> Agent response
```

所以今天完成的是“RAG 参与 Agent 推荐链路”的初步闭环。  
下一步若要完全符合队友口径，需要补强 RAG 注入 LLM prompt/context 的实现与断言。

## 5. 后续建议

### 5.1 优先回修

1. 避免 reranker 双重执行。
   - 当前 `SelfHostedHybridRetriever` 和 `RagRetrievalPipeline` 都可能执行 rerank。
   - 建议统一只在 pipeline 层做 rerank。

2. 明确 embedding key 的部署边界。
   - `VITE_RAG_EMBEDDING_API_KEY` 适合本地 demo。
   - 云端生产不能把真实 key 放进前端 bundle。
   - 后续应改为服务端 proxy 或后端持有 key。

3. 补 RAG -> LLM prompt/context 注入。
   - 在 LLM planner 调用前先 retrieve RAG snippets。
   - 将 snippets 作为“参考规则”进入 prompt/context。
   - 测试断言 prompt 中出现规则文本。

### 5.2 下一步测试目标

建议新增或增强测试：

```text
RAG 规则文档
  -> retrieve
  -> 注入 LLM messages
  -> MockLLMClient 捕获 prompt
  -> 断言 prompt 包含规则
  -> LLM 返回 plan
  -> Agent 输出符合规则的建议
```

这样才能完全回应队友提出的“AG 跟 LM 交互这一部分跑通”的验收要求。

## 6. 通俗解释版

今天做的事情，可以理解成：

我们给 Agent 做了一个“资料室”，里面放了一些时间管理规则，比如：

- 高强度脑力任务适合放在上午。
- 连续学习太久要插入休息。
- 任务安排不能太密。

然后我们测试了 Agent 能不能在和用户对话时去资料室里找这些规则，并把它们用到建议里。

现在的结果是：

Agent 已经能去 RAG 里拿规则了。  
拿到以后，也能把规则反映到用户看到的建议里。  
比如用户说要安排深度阅读、写作、复习这类任务，系统可以引用 RAG 里的“上午优先”“超过 90 分钟要休息”这类规则来给建议。

不过现在还不是最理想的版本。

最理想的版本是：

```text
LLM 自己先看到 RAG 里的规则，
再根据规则思考，
最后生成排期方案。
```

而现在更像是：

```text
Agent 正常处理用户请求，
旁边的 RecommendationHandler 再去 RAG 里拿一条规则，
把这条规则作为建议补充给用户。
```

所以今天的成果可以说是：

RAG 已经能进入 Agent 的实际交互链路，测试也跑通了。  
但下一步还要让 RAG 规则真正进入 LLM 的 prompt 里，让 LLM 在生成方案前就能读到这些规则。

一句话总结：

> 今天我们把 RAG 从“有库、有接口”推进到了“能被 Agent 在对话中实际用起来”，并补了对应测试；但它还没有完全变成 LLM 思考过程的一部分。
